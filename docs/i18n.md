# Internationalization (i18n)

Relaticle ships in English, German, Spanish and French. `config('app.available_locales')` owns the list, and every picker, route, sitemap and test reads it.

## What follows the language

- **The app.** Each user picks a language under Profile, Language. Sign-up seeds it from the `locale` cookie or the browser's `Accept-Language`. `SetUserLocale` applies it to every request and Livewire update, and Laravel `Context` carries it into queued jobs. An unset or retired value falls back to `APP_LOCALE`, the install default.
- **Rela and mail.** Turns Rela opens itself, emails and notifications use the recipient's language.
- **New workspaces.** Built-in attributes, stages and sample records are created in the language of the person who creates the workspace. After that they are ordinary workspace data, so renames stick and nothing is translated on display.
- **The public site.** On relaticle.com every page lives at its English URL and again under `/de`, `/es` and `/fr`, with hreflang alternates and a language switcher. An unprefixed URL always renders English.
- **Help and developer docs.** English lives in `packages/Documentation/resources/content/{help,docs}`, and each other language in `content/{locale}/{help,docs}` with the same paths. Links inside a translated page carry the language prefix (`/de/help/...`), images and blog links stay unprefixed, and `related:` keeps the English page ids.
- **The blog.** Posts carry a language and a translation group (relaticle/ink 2.6). A page links the English post when no translation exists.

These stay English: the system admin panel, MCP tool descriptions, REST API error bodies, the OpenAPI spec, `llms.txt`, console output, logs, exception messages and users' own data. Legal pages show a translated notice above the English text, which governs.

## Fix or improve a translation

Translations were machine-drafted against the glossary below, then reviewed. Native speakers improve them through pull requests:

1. Find the string. Sentence keys live in `lang/{locale}.json` and `packages/*/lang/{locale}.json`, keyed by the English text. Grouped keys live in `lang/{locale}/*.php`. Marketing copy lives in `packages/Cloud/lang`.
2. Change only the value, never the key. Keep every `:placeholder`, HTML tag and plural `|` segment.
3. Follow the glossary and the address rule. Never use an em-dash.
4. Run `php artisan test --compact tests/Arch/TranslationsTest.php tests/Arch/ConventionsTest.php` before opening the pull request.

A help page is fixed the same way in its `content/{locale}` file. `tests/Feature/Documentation/HelpContentIntegrityTest.php` checks its links, headings, front matter and title length.

## Add an English string

1. Wrap it in `__()` with the English sentence as the key.
2. Run `php artisan lang:extract`. It writes the new key to the right `en.json`. CI fails while the catalogue is stale.
3. Add the German, Spanish and French values. `tests/Arch/TranslationsTest.php` fails any English key that ships without all three.

`php artisan locale:diff {locale}` lists missing, orphaned and stale keys for one language, and `--format=json` gives the same as JSON. `--update-snapshot` records the English values a translation was checked against.

## Add a language

1. Add the code to `available_locales` in `config/app.php`.
2. Translate every root that `TranslationsTest` lists, including the vendor overrides in `lang/vendor`, until its rows pass.
3. Translate the help and developer docs into `content/{locale}` until `DocsTranslationParityTest` passes.
4. Add the code to the reserved slugs in `App\Models\Workspace`, so no workspace URL collides with the public prefix.

## Glossary

Every translation uses one word per business concept, the same word in code copy, emails, Rela and the help pages. Words for Filament's own vocabulary (record, view, search) follow the word Filament's `de`, `es` and `fr` files use most, so a page never mixes two words for one thing. The German record is Eintrag: 22 uses in `vendor/filament/*/resources/lang/de` against 5 for Datensatz. A ban applies to the concept named in its cell, never to the word in general.

Address: German "Sie", French "vous", Spanish neutral Latin American "usted" (no "vosotros", no one-country words such as "ordenador" or "computadora"). Rela keeps its name everywhere. The MCP server keeps its English name, written "MCP-Server" in German.

| manage | administrar | gestionar |
| maybe (RSVP) | tal vez | quizás |

| unpaid | sin pagar | impaga |

Four exceptions keep their word because they name something else:

- The opportunity's "Point of Contact" relation is Ansprechpartner, persona de contacto and interlocuteur. "Contact us" and the contact form are a verb and a page, so "Kontakt", "contacto" and "contact" stay there.
- "Konto", "cuenta" and "compte" name the sign-in, never a company or a mailbox.
- The company's "Account Owner" field is Verantwortlicher, responsable and responsable. The account word stays out of it in every language.
- Where English "people" means the humans who use the product, write "you" or "your team": Sie or Ihr Team, usted or su equipo, vous or votre équipe. The record word never stands in for them.

## Locale codes

Relaticle's own codes are two letters (`de`, `es`, `fr`). A regional variant follows ISO 15897 with an underscore (`pt_BR`), never a hyphen, because Carbon and PHP's `intl` silently mismatch hyphenated codes.

## Plural forms

Laravel's pipe syntax (`{0} none|[1,*] some`) handles the plurals of all four languages. A language with more plural forms (Polish: one, few, many, other) uses ICU `MessageFormatter` patterns in its JSON values. `ext-intl` is already required.

## CI guardrails

- `tests/Arch/TranslationsTest.php` fails a stale English catalogue, an English key without its three translations, and a translation whose English key is gone.
- `HardcodedUserFacingStringRule` and `HardcodedStaticPropertyRule` (PHPStan) fail hardcoded user-facing strings in Filament components and class properties. Blade views are not covered, so a reviewer reads for literal text there.
- `tests/Arch/ConventionsTest.php` applies the copy rules (no em-dash, the business words) to every language file.
