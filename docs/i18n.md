# Internationalization (i18n)

Relaticle ships English-only in the main repository. The codebase is fully i18n-ready: every user-facing string in the authenticated app UI is wrapped in `__()` and keyed against `lang/en/`. Forks and self-hosters that want to translate Relaticle drop their `lang/<locale>/` directory in place. No source-file modifications are needed.

## Quick start for fork maintainers

1. Copy `lang/en/` to `lang/<locale>/`:
    ```bash
    cp -r lang/en lang/fr
    ```

2. Translate the strings in `lang/fr/**/*.php`.

3. Refresh the Laravel-Lang framework translations for your locale (auth, validation, pagination, password reset). Relaticle does not ship Laravel-Lang, so install it for the run and remove it after:
    ```bash
    composer require --dev laravel-lang/common
    php artisan lang:update
    composer remove --dev laravel-lang/common
    ```
    Repeat this whenever you add a new locale or want to refresh framework strings.

4. Record a baseline of the English values you just translated against:
    ```bash
    php artisan locale:diff fr --update-snapshot
    ```
    Commit `lang/.snapshots/fr.json` alongside your `lang/fr/` files so teammates share translation state.

5. Set the locale in your `.env`:
    ```
    APP_LOCALE=fr
    ```

6. Filament's admin chrome (~70 locales) is translated automatically, so only the strings under `lang/<locale>/` are yours to maintain.

## Staying in sync after upstream merges

After every `git pull upstream main`, run:

```bash
php artisan locale:diff fr
```

The command reports three kinds of drift:

- `Missing in fr: <key>`. Upstream added a new key, so you need to translate it.
- `Orphaned in fr: <key>`. Upstream removed the key, so it is safe to delete from your locale file.
- `Stale in fr: <key> (current en: "...")`. The English value changed since you last ran `--update-snapshot`. Your translation may now be out of date.

Once you've reviewed and translated, refresh your baseline:

```bash
php artisan locale:diff fr --update-snapshot
```

### Machine-readable output

For tooling (CI checks, IDE plugins, translation dashboards), pass `--format=json`:

```bash
php artisan locale:diff fr --format=json
```

Schema:

```jsonc
{
  "locale": "fr",
  "missing":  [{ "key": "filament/resources/foo.bar", "kind": "php" }],
  "orphaned": [{ "key": "Sign out", "kind": "json" }],
  "stale":    [{ "key": "filament/resources/company.label", "kind": "php", "current_en_value": "company" }]
}
```

Exit code is 0 when all three lists are empty, 1 otherwise.

## Glossary

Every translation uses one word per business concept, the same word in code copy, emails, Rela and the help pages. Words for Filament's own vocabulary (record, view, search) follow the word Filament's `de`, `es` and `fr` files use most, so a page never mixes two words for one thing. The German record is Eintrag: 22 uses in `vendor/filament/*/resources/lang/de` against 5 for Datensatz. A ban applies to the concept named in its cell, never to the word in general.

Address: German "Sie", French "vous", Spanish neutral Latin American "usted" (no "vosotros", no one-country words such as "ordenador" or "computadora"). Rela keeps its name everywhere. The MCP server keeps its English name, written "MCP-Server" in German.

Five more concepts take one word in every language, agreed in the German review. Spanish and French pick one word each and use it everywhere.

| English | Deutsch | Español | Français | Rule |
|---|---|---|---|---|
| reschedule | neu terminieren | reprogramar | reprogrammer | never "verschieben", which means move. French: the "programmer" family, never "planifier" |

| meeting | Meeting | reunión | réunion | never "Termin" |
| assignee | Zuständig | asignado | assigné | the person a task is assigned to. French: the "assigner" family, never "attribuer" |
| unknown user | Unbekannte Person | persona desconocida | personne inconnue | "Mitglied" and "membre" only when the person is a workspace member |
| plan | Tarif | plan | offre | never "forfait". The legacy plan is "Cloud Gratuit (historique)" |
| mass send | Massenversand | envío masivo | envoi en masse | never "groupé" |
| checklist | Checkliste | lista de verificación | liste de contrôle | never "liste de tâches" |
| calendar | Kalender | calendario | agenda | never "calendrier" |

Four exceptions keep their word because they name something else:

- The opportunity's "Point of Contact" relation is Ansprechpartner, persona de contacto and interlocuteur. "Contact us" and the contact form are a verb and a page, so "Kontakt", "contacto" and "contact" stay there.
- "Konto", "cuenta" and "compte" name the sign-in, never a company or a mailbox.
- The company's "Account Owner" field is Verantwortlicher, responsable and responsable. The account word stays out of it in every language.
- Where English "people" means the humans who use the product, write "you" or "your team": Sie or Ihr Team, usted or su equipo, vous or votre équipe. The record word never stands in for them.

## Locale codes

We follow ISO 15897: underscores, not hyphens. Use `pt_BR`, `zh_CN`, `en_GB`. Mismatches break Carbon and PHP's `intl` silently.

## Plural forms

Laravel's pipe syntax (`{0} none|[1,*] some`) handles English-style plurals. For Slavic languages with multiple plural forms (Polish: one/few/many/other), use ICU `MessageFormatter` patterns in JSON values. The `ext-intl` extension is required (already in `composer.json`).

## Out of scope

These are **not** translated and probably shouldn't be:

- Marketing pages (homepage, pricing, contact, public landing pages), because translation breaks SEO without per-locale routing
- Exception messages and log output, which are internal and dev-facing
- Validation rule messages already covered by Laravel's shipped translations (override only what we customize via `lang/vendor/`)

## Distribution

Relaticle does not operate a Crowdin/Weblate hub. If your fork develops well-maintained translations and you want to share them with the community, open a discussion on GitHub and we'll point future translators at your repo.

## CI guardrails

A pair of custom Larastan rules (`HardcodedUserFacingStringRule`, `HardcodedStaticPropertyRule`) prevents new code from introducing hardcoded user-facing strings in Filament components and class properties.

Missing-key typos (e.g. `__('typo.key')` referencing a key that doesn't exist) are not caught by static analysis. They surface as the literal key string in the rendered UI during QA.

If `composer test:types` flags i18n violations, fix them before merging. Do not add to the baseline.

## Example fixture

`lang/fr/filament/resources/company.php` is committed as a working example of how a fork's translation file looks. It demonstrates the override path end-to-end and is verified by `tests/Browser/I18nCompanyResourceTest.php`.
