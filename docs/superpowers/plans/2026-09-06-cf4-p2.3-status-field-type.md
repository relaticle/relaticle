# Custom Fields 4.0, Plan 2.3: The Status Field Type

> **For agentic workers:** REQUIRED SUB-SKILL: sdd-lean, task-by-task. Runs on the package `feat/4.0` branch AFTER plans 2.1, 4.1 and 4.3 have landed (the options editor is reshaped once by then). Implements the 2026-09-06 amendment to the phase 2 spec. Package quality gate per task, plus the UI rule for every touched screen.

**Goal:** Option categories belong to a dedicated `status` field type, not to every single-choice select. A Status field is a single-choice field whose options each carry a category (`unstarted`, `started`, `completed`, `cancelled`); a plain Select never shows a category column. Record, Relationship and Status are three distinct field types and are never combined.

**Why this plan exists:** plan 2.1 put `settings.category` on every single-choice select behind a flag. The maintainer decided on 2026-09-06 that the semantic belongs to its own type: a user picking "Status" gets categorized options by construction, and a user picking "Select" keeps a plain list. Storage does not change (`settings.category` on `custom_field_options`, a single option id per value), so no migration is needed and the query surface from plan 2.1 stays.

**Decisions:**

1. New field type `status` (`StatusFieldType`, `FieldDataType::SINGLE_CHOICE`), registered by default, listed in the type picker with its own icon and description. Components: the same select input, badge column, entry and select filter the Select type uses, so a Status field looks like a Select everywhere a value is shown.
2. The options editor shows the category column only for Status fields, always (no flag). A Status option without a category is allowed (null means unknown) but the editor nudges: the column is visible and the placeholder says so.
3. The `FIELD_OPTION_CATEGORIES` flag retires: a field type is offered or not through the type registry, which hosts already control. Remove it from the enum, the config, the docs and the flag tests; the upgrade guide records the removal.
4. `CustomField::optionsInCategory()` and `CustomFieldOption::scopeWhereCategory()` stay as the read API; on a non-Status field they return an empty collection.
5. The migrator's per-option `category` key is accepted for Status fields only and rejected with a clear message elsewhere.
6. A Select field can be converted to a Status field by changing `type` on the row (same storage). The package ships no conversion tool; the host backfill (plan 2.2 Task 2) does it for the seeded status and stage fields.

### Task 1: The type

- `src/FieldTypeSystem/Definitions/StatusFieldType.php`: key `status`, label and description lang keys, `FieldDataType::SINGLE_CHOICE`, the Select type's components, `filterable`, `sortable`, `searchable` as Select has them, a capability `carriesOptionCategories()` on `FieldSchema`/`FieldTypeData` set only here.
- Register in `DEFAULT_FIELD_TYPES`; type picker entry; docs field-types page.
- Tests: create a Status field through the management form, set values, filter and sort, both flavors of the type picker list it.

### Task 2: The options editor

- `FieldForm` options repeater: the category column is visible when the field type carries option categories (read through `Get` as the color column does), never on Select, never behind a flag. Remove `FIELD_OPTION_CATEGORIES` from `CustomFieldsFeature`, `config/custom-fields.php`, the configuration docs table, `FeatureSystemTest` and every test that toggled it.
- The settings merge from plan 2.1 (hidden columns keep stored keys) stays.
- Tests: the column renders on a Status field and not on a Select; a stored category survives an edit on a Select (should never happen, but the merge guarantees it).

### Task 3: Migrator and docs

- `CustomFieldsMigrator::createOptions()` accepts `category` for Status fields, rejects it for every other type naming the field; `lookupType()`-style helper for presets to declare a Status field.
- Docs: `9.option-categories.md` rewritten around the Status type (vocabulary, terminal semantics, the read API, a host recipe seeding a Status field with categories through the migrator, the conversion note); upgrade guide: the flag removal and "Status is new; Select is unchanged".
- Verify: full gate on all three drivers; docs build.
