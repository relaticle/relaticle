# Custom Fields 4.0, Plan 2.2: Option Categories on the Host

> **For agentic workers:** REQUIRED SUB-SKILL: sdd-lean, task-by-task. Runs in the relaticle/relaticle repo AFTER Plan 2.1 is merged on the package side (against the `4.x` branch via path repository, or against a 3.x minor if the phase 2 backport decision was taken). Relaticle gates apply (pint, rector, phpstan level 7, type coverage 100, targeted pest; `composer test:pest:full` before push). Spec: 2026-09-03-cf4-p2-option-categories-spec.md. Closes relaticle/relaticle#556 from the shipping PR.

**Goal:** Delete every literal status lookup in Relaticle by consuming `settings.category`, seed categories for new workspaces, backfill existing tenants by seeded name, and expose the category to agents and integrations.

**Hard rule:** all reads go through `App\Models\CustomFieldOption` (arch rule); sweep `packages/SystemAdmin` for any `match` over the new enum, since that package is excluded from PHPStan.

### Task 1: Seeds

- `app/Enums/CustomFields/TaskField.php` and `OpportunityField.php` gain `getOptionCategories()` beside `getOptionColors()`: To do `unstarted`, In progress `started`, Done `completed`; Prospecting `unstarted`, the middle stages `started`, Closed Won `completed`, Closed Lost `cancelled`.
- `app/Listeners/CreateTeamCustomFields.php:100-110` passes the category into the migrator `options()` payload so new workspaces are categorized from day one.
- Verify: a new-team test asserts every seeded status and stage option carries the expected category.

### Task 2: Backfill command

- `custom-fields:backfill-categories`, copied from `app/Console/Commands/BackfillCustomFieldColorsCommand.php` (`--dry-run`, `--team`). Matches options by seeded name per tenant and writes `settings.category`; renamed options stay null and are listed in the summary so support can follow up.
- Runs once in the same release as the package bump, after the substrate migration when both ship together.
- Verify: command test on a fixture tenant, dry-run (no writes, full report) and real; a renamed option is reported and left null.

### Task 3: Delete the literal lookups

- `app/Actions/Task/CompleteTask.php:35`, `packages/Chat/src/Services/MyTasksService.php:133`, `app/Services/Notifications/DigestService.php:109`, `app/Actions/Crm/GetCrmSummary.php:123`: each resolves the first `completed` option of the status field instead of the name `Done`.
- Rename `hasDoneOption` and `done_option_id` to category language so `app/Filament/Pages/Dashboard.php:115` reads true.
- The 422 in `CompleteTask` becomes "no completed task status", still raised when the category is unset.
- Verify: Feature tests on a tenant whose Done option is renamed: complete a task, read the digest, read my-tasks; all succeed with zero label matching.

### Task 4: Won revenue

- Restore won revenue in `GetCrmSummary` as the sum over opportunities whose stage option is `completed`, with `cancelled` reported as lost. This reverses the #549 removal on category, never on label.
- Verify: the fixture renames Closed Won and asserts the figure still reports.

### Task 5: Expose the category

- `packages/Chat/src/Services/Tools/CustomFieldsSchemaDescriber.php:30` eager-loads `options:id,custom_field_id,name`; add `settings` or the category is invisible to the model. Describe the category next to each option label.
- `GetCrmSchemaTool` and `ListCustomFieldsTool` expose it; the REST option shape gains `category`; Scribe regenerates.
- Verify: schema describer output test; API resource test; MCP schema test.
