# Custom Fields 4.0, Plan 2: Relationship UI and Field-Management Polish

> **For agentic workers:** REQUIRED SUB-SKILL: sdd-lean, task-by-task. Runs on the `4.x` branch AFTER Plan 1 (substrate); every service this plan renders against (CreateRelationshipDefinition, LinkWriter, LinkReader, the events) exists by then. Package quality gate per task, plus the UI rule: every screen is verified with agent-browser click-throughs (light AND dark, mobile viewport, empty states) before any done claim. Package UI stays themeable; no host styling leaks in.

**Goal:** Implement spec section 3: the relationship creation flow, the record-side experience, the field-management polish pass, and the flavor registry that carries all of it in two presentations over one logic layer.

**Decision context:** the flavor registry was re-examined in the 2026-09-01 architecture review and explicitly KEPT. The accepted cost (15 to 20 percent on UI work, doubled browser CI on critical paths) is bounded by the rule below: logic never forks; only views fork, and only on the four polished surfaces.

### Task 1: Flavor registry foundation

- Config: `ui.flavor` (`polished` default, `native`) plus a per-component override map.
- A view-resolution helper the four custom surfaces render through: polished resolves to the package's custom Blade views, native to stock Filament rendering of the same Livewire classes.
- The four forked surfaces, and ONLY these: relationship configurator, record chips and picker, type-picker grid, attribute table. Everything else uses stock Filament in both flavors.
- Test: unit-level resolution (flavor + override map), and a Livewire render smoke of one surface in each flavor.
- Build this FIRST so Tasks 2 to 4 route through it from the start instead of retrofitting.

### Task 2: Relationship creation flow

- Create-attribute flow, type Relationship: two entity cards with the cardinality selector between them reading as a sentence; per-side associated-attribute name inputs with smart defaults; the sync banner as education; a symmetric toggle when both ends match, collapsing to one name input; cmd+enter submits.
- Machine code auto-generated from the names, editable under an Advanced disclosure; uniqueness validated per tenant.
- Submission calls `CreateRelationshipDefinition` (one transaction, 0 to 2 fields); the form never writes models directly.
- Lifecycle editing per spec 2.3: cardinality change allowed with keep-first confirmation when narrowing to a single side; entity-type ends locked after create; unpair and delete via the Plan 1 services.
- Tests: Livewire component tests for each cardinality, symmetric, the narrowing confirmation, and validation errors; browser click-through of the full flow.

### Task 3: Record chips and picker

- Chips with avatars and click-through; ordered chips with +N overflow, never a bare count.
- Picker: debounced instant search, avatars, keyboard navigation, inline create-new.
- Unlink on the chip; the one-to-one steal confirms inline before the writer resolves it.
- Provenance on hover from the ledger: actor and relative time (changed by X, 2d ago), read from the link row's created_by and active_from.
- All reads through `LinkReader` and the preloaded link relations; no N+1 on tables (assert query count in tests).
- Tests: Livewire interaction tests (search, select, reorder, unlink, steal confirm); browser click-through including empty state.

### Task 4: Field-management polish pass

- Searchable type-picker grid with icons and descriptions.
- Attribute table: reorder handles, type icons, badges, inline activate; relationship pairs visually connected across their two rows.
- Educational empty states; slide-over editing with cmd+enter; loading skeletons; full dark-mode audit.
- FieldForm's record configuration is replaced by the Task 2 flow (the last `lookup_type` writers die in Plan 3).
- Tests: table interaction tests; browser pass over every management screen.

### Task 5: Bulk paste for choice options

Spec 3.3. Today the options repeater (`src/Filament/Management/Schemas/FieldForm.php:170`) adds one option per click, so a 200-value vocabulary is 200 clicks.

- A `hintAction()` on the options repeater opens a modal with a textarea, one option name per line. Stock Filament, so it renders identically in both flavors and needs no fork. The repeater sets `hiddenLabel()`, so confirm the hint still renders; fall back to an `Actions` component beside it if not.
- Parse in a small final class (split lines, trim, drop blanks). Dedupe case-insensitively within the paste AND against existing rows, matching the repeater's own duplicate rule (`FieldForm.php:186-204`) so the pasted result never fails validation.
- Append through repeater state, mirroring `Repeater::getAddAction()`: `getRawState()`, a key per item from `generateUuid()`, then `getChildSchema($uuid)->fill(['name' => $name])`, then `rawState()` and `callAfterStateUpdated()`. NEVER `CustomFieldOption::create()` directly, which would bypass the tenant stamping in `mutateRelationshipDataBeforeCreateUsing` and the `sort_order` ordering.
- `defaultItems(1)` means a fresh field opens with one blank row. Drop a single blank row when the paste lands, or the form fails `required` on a row the user never typed.
- Cap the paste (start at 100, class constant, not a config key) and report the truncation in the result notification: "42 added, 3 duplicates skipped". The cap protects the Livewire payload on a large repeater, not the database; revisit it if Task 4 makes the options editor lighter.
- Names only. No `Name, #hex` parsing: the color column is conditionally visible (`FIELD_OPTION_COLORS` plus `enable_option_colors`), so a two-column format reads wrong on most tenants. Pasted rows leave `settings.category` (Plan 5) null, which is the correct unknown state; the user sets categories in the editor afterwards.
- i18n: new keys under `field.form.options` in `resources/lang/en/custom-fields.php` (`en` is the only locale). No new feature flag; the action inherits the repeater's visibility.
- Tests: parser cases (blanks, casing, duplicates, cap); a Livewire test asserting appended state, key generation and the dropped blank row; browser click-through of the modal in both flavors.
